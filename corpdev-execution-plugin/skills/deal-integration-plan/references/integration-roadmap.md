# Reference — Integration Roadmap (2/4/6-Month Milestone Patterns)

Operationalize the integration approach (the keep/rebuild/discard plan from technical diligence) into
milestones at 2, 4, and 6 months. Pick the pattern by deal type, then tailor.

## Pattern A — Talent acqui-hire (team is the thesis)
- **Month 2:** team fully onboarded; reporting lines + Toast tooling live; retention agreements
  bedded in; first contributions to Toast roadmap scoped
- **Month 4:** team shipping on Toast priorities; legacy product sunset/migration underway (if any);
  key-person retention holding
- **Month 6:** team fully productive on Toast roadmap; retention at target; legacy fully wound down

## Pattern B — Product tuck-in (product to integrate)
- **Month 2:** integration path locked (keep/rebuild/discard confirmed); data migration started;
  Day-1 customer continuity holding
- **Month 4:** acquired product integrated into Toast surface (beta/limited GA); first cross-sell to
  Toast customers; support fully transitioned
- **Month 6:** GA in Toast product; cross-sell motion converting; legacy stack decommissioned per plan

## Pattern C — Platform (standalone product, scaled)
- **Month 2:** governance + OKRs live; customer base stable; integration architecture decided
- **Month 4:** first integration milestones shipped; revenue/retention tracking to thesis; org aligned
- **Month 6:** material integration milestones delivered; synergy/revenue targets on track; roadmap merged

## Cross-cutting at every milestone
- **Retention check** (acquired team) — the leading indicator of integration health
- **Delivery vs. OKR** — RAG status on each KR
- **Financial/business metrics** — adoption, attached ARR, synergy run-rate, cost
- **Risks/blockers** surfaced to the Exec Sponsor

## Cadence
2–3×/week for the first 30 days (highest-risk window), then weekly. `integration-tracker` runs it.
